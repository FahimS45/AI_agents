Getting Started with LangGraph Agent System — Beginner-Friendly Guide

Introduction

  • What this tool is:

    This guide introduces a graph-based orchestration approach (LangGraph-style) for composing multiple small programs called "agents" into larger AI workflows. Each agent does one focused job (for example: translate text, detect language, or apply glossary terms), and the orchestrator (the graph) coordinates them and passes data along.

  • Why beginners should learn it:

    Learning this approach helps you design modular, testable AI systems. It encourages building small, reusable pieces (agents) instead of one large monolith — this makes debugging and extending systems much easier. The guide uses practical examples and runnable code so you can experiment step-by-step.

  • What you'll learn in this guide:

    You will learn the core concepts, the minimum setup to run a simple translation pipeline, clear definitions of terms before they appear in code, complete example files (with comments), how to run the example locally (including a safe fallback if you don't have an API key), and common troubleshooting steps.

Prerequisites

This guide assumes no prior experience with LangGraph. Minimal programming familiarity (running Python scripts and installing packages) helps, but every technical term is defined before it is used.

Definitions (simple and up front)

  • Agent — a small, focused program component that performs a single task (for example: "translate text from English to French").
  • Orchestrator / Graph — a controller that runs agents in a specified order and passes data between them. Think of it as a map of which agents are connected.
  • State — information carried as the workflow progresses (e.g., a glossary, user preferences). State is usually a dictionary-like object you pass between agents.
  • LLM (Large Language Model) — a model like GPT-4o that can generate or transform text. It is used as the "brain" for tasks such as translation.
  • Embedding — a numeric vector representation of text that captures semantic meaning.
  • Vector store — a database optimized to save and search embeddings quickly (examples: Chroma). Useful for memory and retrieval.

System & software

  • OS: Linux, macOS, or Windows (WSL is an option on Windows).
  • Python: 3.10 or 3.11 recommended.
  • pip: Python package installer (comes with Python in most setups).
  • OpenAI API key (optional): If you want to call OpenAI models. If you don't have one, the examples include a harmless local fallback so you can try the end-to-end flow without a key.

Core concepts (short, focused)

agents.py — Agent implementations (complete and runnable)

This file includes a robust call_llm helper that uses OpenAI when an API key is present, and a deterministic fallback when it's not. This makes the examples runnable for beginners.

# agents.py
"""
Simple agent classes for the tutorial.

- call_llm: helper to call an LLM. If OPENAI_API_KEY is present, it calls OpenAI's ChatCompletion.
  If not present, it returns a deterministic fallback (useful for local testing without an API key).

- TranslateAgent: accepts a request and state, builds a prompt with optional glossary terms,
  and returns a dictionary with a "translation" key.

Notes:
- This helper uses the openai package. If you have an API key, set the environment variable
  OPENAI_API_KEY. If not set, the fallback will run so you can test the pipeline end-to-end.
"""

import os
import json
import openai

def call_llm(prompt, model="gpt-4o", max_tokens=1000, temperature=0.0):
    """
    Call an LLM (OpenAI ChatCompletion). If OPENAI_API_KEY is not set, return a deterministic
    fallback translation (not a real translation, but consistent for testing).

    Returns a string with the LLM output.
    """
    api_key = os.environ.get("OPENAI_API_KEY")
    # Clean inputs
    if prompt is None:
        prompt = ""
    # If API key is missing, provide a deterministic mock response that shows what would happen.
    if not api_key:
        # Very small mock: for French target, replace a few common English words with French.
        # This is intentionally simple and deterministic for testing.
        replacements = {
            "Hello": "Bonjour",
            "hello": "bonjour",
            "How are you": "Comment ça va",
            "how are you": "comment ça va",
            "Thank you": "Merci",
            "thank you": "merci"
        }
        text = prompt
        # naive attempt to extract "Translate the following text to X:\n\n{TEXT}"
        marker = "Translate the following text to"
        try:
            # extract last block after colon or double newline
            if marker in prompt:
                # find the last double newline and take what follows as the user's text
                parts = prompt.split("\n\n")
                candidate = parts[-1].strip()
            else:
                candidate = prompt.strip()
        except Exception:
            candidate = prompt.strip()

        fallback = candidate
        for k, v in replacements.items():
            fallback = fallback.replace(k, v)
        # If target information is in the prompt, append an indicator for clarity
        if "to fr" in prompt.lower() or "to french" in prompt.lower() or "to fr" in prompt.lower():
            fallback = fallback + " [mock-translated to French]"
        else:
            fallback = fallback + " [mock-translated]"
        return fallback

    # If API key is present, make a real call to OpenAI ChatCompletion API.
    openai.api_key = api_key
    # Build messages as a single user message. For production, follow OpenAI's recommended chat format.
    try:
        response = openai.ChatCompletion.create(
            model=model,
            messages=[{"role": "user", "content": prompt}],
            max_tokens=max_tokens,
            temperature=temperature
        )
        # Extract text safely
        choices = response.get("choices", [])
        if not choices:
            return ""
        message = choices[0].get("message", {})
        text = message.get("content", "").strip()
        return text
    except Exception as e:
        # Surface a readable error for beginners
        raise RuntimeError(f"LLM call failed: {e}")


class TranslateAgent:
    """
    TranslateAgent expects:
      - request: dict with keys:
          - 'text': the text to translate (required)
          - 'target': target language (e.g., 'fr' or 'french') (required)
          - 'source': optional source language (default 'auto')
      - state: dict-like; may contain 'terminology' mapping (source term -> preferred target term)

    Returns:
      - dict with key 'translation' whose value is the translated text.
    """

    def __init__(self, config=None):
        # config is a dictionary; allow specifying model and other parameters
        self.config = config or {}
        self.model = self.config.get("model", "gpt-4o")
        # You can add model-specific options here
        self.max_tokens = self.config.get("max_tokens", 1000)
        self.temperature = self.config.get("temperature", 0.0)

    def handle_request(self, request, state):
        # Validate request
        if not isinstance(request, dict) or "text" not in request or "target" not in request:
            raise ValueError("request must be a dict with keys 'text' and 'target'")

        text = request["text"]
        target = request["target"]

        # Pull terminology (glossary) from state if present
        terminology = {}
        if isinstance(state, dict):
            terminology = state.get("terminology", {}) or {}

        # Build a clear prompt. Ask the model to return ONLY the translation text.
        prompt_lines = [
            f"Translate the following text to {target}.",
            "Return only the translation text in plain output (no explanations).",
            "",
            "Text to translate:",
            text,
            ""
        ]

        if terminology:
            # Provide glossary terms to prefer during translation
            prompt_lines.append("Use the following glossary where applicable (SourceTerm -> PreferredTargetTerm):")
            for src_term, tgt_term in terminology.items():
                prompt_lines.append(f"- {src_term} -> {tgt_term}")
            prompt_lines.append("")  # blank line for clarity

        prompt = "\n".join(prompt_lines)

        # Call LLM (or fallback if no API key)
        translation = call_llm(
            prompt,
            model=self.model,
            max_tokens=self.max_tokens,
            temperature=self.temperature,
        )

        # Return a structured response so the orchestrator can inspect results
        return {"translation": translation}

Code explanation — agents.py (high-level)

  1. The call_llm helper first checks if an OpenAI API key is available. If not, it returns a deterministic mock response so you can run the pipeline locally without network calls.
  2. TranslateAgent shows the simple agent API pattern: constructor accepts config, handle_request receives request and state and returns a result dict.
  3. Prompts ask the model to "Return only the translation text" to reduce unpredictable output formatting.

main.py — Graph construction and run (self-contained and runnable)

To make the example work for beginners even without an external LangGraph package, the following small Graph and AgentNode implementations are included. If you have a real orchestration library, you can adapt the pattern.

# main.py
"""
Small, self-contained graph implementation to demonstrate agent orchestration.
This file:
- Implements a minimal Graph and AgentNode wrapper
- Implements a CoordinatorAgent that routes requests to language-specific translators
- Builds and runs the graph with a sample request and state

Note: This is intentionally small and synchronous to keep things simple for beginners.
"""

from agents import TranslateAgent
import traceback

# Minimal wrapper to hold an agent instance and its name
class AgentNode:
    def __init__(self, name, agent):
        self.name = name
        self.agent = agent

# Minimal Graph class to hold nodes, edges, and perform calls
class Graph:
    def __init__(self):
        self._nodes = {}  # name -> AgentNode
        self._edges = {}  # (src, dst) -> message types (not used heavily here)

    def add_node(self, node: AgentNode):
        if node.name in self._nodes:
            raise ValueError(f"Node '{node.name}' already exists")
        self._nodes[node.name] = node

    def add_edge(self, src, dst, msg_type=None):
        # For simplicity: ensure nodes exist and record the edge
        if src not in self._nodes or dst not in self._nodes:
            raise ValueError("Both src and dst must be added before creating an edge")
        self._edges.setdefault(src, []).append((dst, msg_type))

    def call_node(self, node_name, request, state):
        """
        Invoke the agent attached to node_name and return result.
        If the agent expects an extra parameter (like a graph), try providing it.
        """
        if node_name not in self._nodes:
            raise KeyError(f"Node '{node_name}' not found in graph")

        node = self._nodes[node_name]
        agent = node.agent

        try:
            # Try calling with (request, state, graph) — some agents may want the graph.
            try:
                return agent.handle_request(request, state, self)
            except TypeError:
                # Fallback: call with (request, state)
                return agent.handle_request(request, state)
        except Exception as e:
            # For beginners: show a helpful traceback
            tb = traceback.format_exc()
            return {"error": str(e), "traceback": tb}


# CoordinatorAgent chooses which translator (node) to call based on target language
class CoordinatorAgent:
    def __init__(self, config=None):
        self.config = config or {}

    def handle_request(self, request, state, graph):
        """
        request: dict with 'text' and 'target'
        state: dict-like
        graph: Graph instance so the coordinator can call other nodes
        """
        target = request.get("target", "").lower()
        # Basic routing rules
        if target.startswith("fr") or "french" in target:
            node_name = "translate_fr"
        else:
            node_name = "translate_en"

        # Call the chosen translator node
        result = graph.call_node(node_name, request, state)
        # Optionally post-process here (not required for the simple demo)
        return result


def build_graph(config=None):
    """
    Build and return a Graph instance configured with:
    - coordinator node
    - translate_en node
    - translate_fr node
    """
    cfg = config or {}
    g = Graph()
    # Coordinator node
    coordinator = AgentNode("coordinator", CoordinatorAgent(cfg))
    g.add_node(coordinator)
    # Two translator nodes using the same TranslateAgent class but can receive different configs
    en_agent = AgentNode("translate_en", TranslateAgent({"model": cfg.get("model", "gpt-4o")}))
    fr_agent = AgentNode("translate_fr", TranslateAgent({"model": cfg.get("model", "gpt-4o")}))
    g.add_node(en_agent)
    g.add_node(fr_agent)
    # Add edges to indicate allowed calls (used for validation in more advanced systems)
    g.add_edge("coordinator", "translate_en", "task_req")
    g.add_edge("coordinator", "translate_fr", "task_req")
    return g


if __name__ == "__main__":
    # Sample configuration
    config = {"model": "gpt-4o"}

    # Build the graph
    graph = build_graph(config)

    # Example request and state
    request = {
        "text": "Hello, how are you?",
        "target": "fr"   # means translate to French
    }
    # Provide a small terminology/glossary so the translation can prefer certain terms
    state = {
        "terminology": {
            "Hello": "Bonjour"
        }
    }

    # Run the workflow by calling the coordinator node
    response = graph.call_node("coordinator", request, state)
    print(response)

Common Patterns and Use Cases (practical guidance)

  • Pipeline pattern — Agents run sequentially (e.g., DetectLanguage → Normalize → Translate → PostEdit). Use when order matters.
  • Specialized agents pattern — One agent per language or domain (TranslateEnAgent, TranslateFrAgent). Use for language-specific rules or models.
  • Coordinator + Worker pattern — Coordinator splits a larger document into paragraphs and sends them to worker translators in parallel (or one-by-one), then merges results. Use for scaling and fault isolation.

Troubleshooting — common beginner issues and fixes

  1. Module import errors (e.g., package not found)
    1. Cause: Package not installed in the active Python environment.
    2. Fixes:
      • Ensure you are using the correct Python interpreter (python --version) and that pip installs to that interpreter.
      • Install packages with pip install openai (and other required packages).
  2. OPENAI_API_KEY not set
    1. Cause: Environment variable not defined.
    2. Fixes:
      • Set it in your shell when you want to use OpenAI: for macOS/Linux: export OPENAI_API_KEY="sk-..."; Windows PowerShell: $env:OPENAI_API_KEY="sk-...".
      • For the examples in this guide, you can run them without a key — the code has a mock fallback.
  3. LLM responses include extra commentary or formatting
    1. Cause: Prompt didn't explicitly request a plain output.
    2. Fixes:
      • Ask the LLM to "Return only the translation text in plain output (no explanations)".
      • Set temperature=0.0 for more deterministic output.
      • Validate and sanitize output in code (for example, strip leading/trailing whitespace and remove surrounding quotes).
  4. Graph call fails: node not found
    1. Cause: Node not added to the graph or misspelled when calling.
    2. Fixes:
      • Check that every node is added with g.add_node(...) and that you call the exact node name.
      • Print available nodes (e.g., print(list(g._nodes.keys()))) to debug names.
  5. Vector store errors (Chroma/permissions)
    1. Cause: File path or permissions issues when using an on-disk vector store.
    2. Fixes:
      • Ensure the configured path exists and is writable (create directory if needed).
      • For initial experiments consider an in-memory vector store to avoid disk permissions issues.

Next steps (technical growth path)

  • Replace the simple call_llm helper with a production-grade client (for example, LangChain LLM wrappers) when you are ready to integrate advanced retry and batching features.
  • Introduce a dedicated ContextManagerAgent to handle session history, TTL (time-to-live) for ephemeral memory, and retrieval from a vector store for contextually augmented responses.
  • Improve agent interfaces by adding lifecycle methods such as init(config), persist_state(state), and rollback() for graceful error handling.
  • Instrument observability: add structured logging and save intermediate agent outputs to help debugging.
  • For translation evaluation, explore metrics like BLEU and ROUGE or human-in-the-loop checks for production quality.
